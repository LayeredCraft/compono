## MeterFactoryTestingExtensions Class

Direct inspection and fluent verification over any [System\.Diagnostics\.Metrics\.IMeterFactory](https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.metrics.imeterfactory 'System\.Diagnostics\.Metrics\.IMeterFactory') \- no assertion framework
required\. Every method here requires the [System\.Diagnostics\.Metrics\.IMeterFactory](https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.metrics.imeterfactory 'System\.Diagnostics\.Metrics\.IMeterFactory') it's called on to actually be a
[CapturingMeterFactory](Compono.Metrics.CapturingMeterFactory.md 'Compono\.Metrics\.CapturingMeterFactory') \(produced by [UseMetrics\(this CompositionBuilder\)](Compono.Metrics.CompositionBuilderExtensions.UseMetrics(thisCompono.CompositionBuilder).md 'Compono\.Metrics\.CompositionBuilderExtensions\.UseMetrics\(this Compono\.CompositionBuilder\)'), or
directly via [CapturingMeterFactory](Compono.Metrics.CapturingMeterFactory.md 'Compono\.Metrics\.CapturingMeterFactory')'s public constructor\) \- calling any of these against a
substitute, a `Compono.TestDoubles`\-generated double, `DefaultMeterFactory`,
or any other non\-Compono [System\.Diagnostics\.Metrics\.IMeterFactory](https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.metrics.imeterfactory 'System\.Diagnostics\.Metrics\.IMeterFactory') throws immediately, diagnostically, rather than
returning an empty/default result\. See docs/adr/0072\-compono\-metrics\-testing\-support\-package\.md's
"Precedence and misuse" section\.
