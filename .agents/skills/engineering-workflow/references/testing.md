# Testing

**Do not use the `dotnet-unit-testing-patterns` skill's AutoFixture
guidance in this repo**, even though that skill is the usual default for
.NET test infrastructure. Compono is itself a from-scratch AutoFixture
replacement (`docs/manifesto.md`) — dogfooding AutoFixture inside
Compono's own test suite would directly contradict the product this repo
exists to build. NSubstitute (mocking) and AwesomeAssertions (assertions)
don't have that conflict and are used normally; only the automatic test-
data-generation piece is out.

`test/Compono.Tests` is the first (and currently only) test project —
these are the conventions to hold new test projects to, not a description
of a large established pattern yet:

- xUnit v3 on Microsoft Testing Platform v2 (`xunit.v3.mtp-v2` package,
  not plain `xunit.v3` — see the comment on that `PackageVersion` in
  `Directory.Packages.props` for why: the plain meta-package resolves an
  MTP-v1-compatible core that throws `TypeLoadException` against a newer
  directly-referenced `Microsoft.Testing.Platform`).
- One test project per src project, same name + `.Tests` suffix (e.g.
  `Compono.Tests` for `src/Compono`), and it stays that way — don't
  consolidate tests across projects, even once `Compono.Xunit`/
  `Compono.NSubstitute`/`Compono.Bogus` exist as separate projects.
- Global usings for `Xunit`, `NSubstitute`, `AwesomeAssertions` are set
  per test csproj — copy that block when creating a new test project.
- Test data is handwritten/explicit (`[InlineData]`, a plain object
  initializer, a small local builder method) rather than generated by a
  fixture library — there is no `[XxxAutoData]`-style attribute or shared
  fixture factory in this repo, and that's deliberate, not a gap to fill
  in later. Once Compono itself is far enough along, Milestone 7
  ("Dogfooding") is the point where Compono's *own* test suite should
  start composing its own test data with Compono — that's the intended
  replacement for what a fixture library would otherwise be doing here,
  not AutoFixture.
- Arrange-Act-Assert with blank-line separation between the three sections,
  no exceptions.
- Given that Compono's own product goal is deterministic composition
  (`README.md`'s "Deterministic by design"), tests for anything seed- or
  randomness-dependent should assert on a fixed seed rather than a
  property-based "run it many times and hope" approach — a flaky test here
  would be a direct contradiction of the thing the library promises to do.
